# STOCKOLON 26

Flask 기반 동아리 모의주식 게임입니다. 주가 계산과 이력 저장은 서버에서 수행합니다.

## 로컬 실행

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python run.py
```

`.env`의 `SECRET_KEY`는 충분히 긴 임의 문자열로 설정합니다. 실제 로그인·회원가입에는
기존 Supabase `users` 테이블과 `SUPABASE_URL`, `SUPABASE_KEY`가 필요하고,
이메일 인증에는 HTTP 이메일 API(Brevo/Resend) 또는 로컬 Gmail 발송 설정이 필요합니다. `.env`와 시장 DB를 커밋하지 않습니다.

주가 엔진과 시장 CLI는 Supabase 접속 없이 실행할 수 있습니다.

```bash
# 현재 시점까지 한 번 갱신
flask --app run market tick
# 접속자가 없어도 30초마다 저장하려면 별도 프로세스로 실행
flask --app run market tick --watch
# 자동 검증 (외부 DB/메일 연결 없음)
python -m unittest discover -s tests -v
```

웹 서버만 실행해도 `/api/market` 조회 시 지난 틱을 복구합니다. 무료 Render에서는 이 방식으로
운영하며, 항상 실행 가능한 환경에서는 같은 DB를 사용하는 `market tick --watch`를 추가할 수 있습니다. Flask 개발 서버는 로컬 개발용입니다.

## 주가 변동 설계 및 구현 (2026-10-29)

### 목표와 구현 범위

매 틱 독립적인 큰 난수를 뽑는 대신 **전체 시장 → 분야 → 개별 동아리**의 흐름에
뉴스와 유저 거래를 더합니다. 같은 분야 종목은 공통 흐름을 공유하지만 개별 사건으로
다르게 움직일 수 있습니다. 미래의 상승·하락 횟수나 경로는 미리 정하지 않습니다.

현재 구현: 33개 종목, 가격 엔진, 영속 이력, 5분 OHLCV 집계, 인증된 조회 API,
종목 카드/상세 차트의 실제 이력 연결, 중단 후 복구, 시장 갱신 CLI.

추가 구현: 관리자 전용 뉴스 발행 화면과 일반 뉴스 목록. 발행한 기사는 시장 이벤트와 함께 저장됩니다.
모의 매수·매도 체결과 현금·보유 종목·포트폴리오를 연결했습니다. 자동 뉴스 발행과 실제 순위 계산은 후속 작업입니다.
확인되지 않은 자산·보유량은 가짜 숫자 대신 `—`로 표시합니다.

### 실제 거래 구조와 게임의 차이

실제 시장은 매수·매도 주문의 가격 조건이 맞아 체결되며 거래 가격이 형성됩니다.
[실제 주식 거래 구조](https://ag.ny.gov/resources/individuals/investing-finance/how-financial-markets-work)

스톡콜론은 적은 참여자 수에서도 시장이 움직이도록 **서버가 거래 상대가 되는
모의시장**으로 운영합니다. 표시된 기준가를 바탕으로 매수·매도 호가를 정하고 모의 현금으로 체결합니다.
주문장·실제 거래소 매매 규칙을 재현한 시스템은 아닙니다.

### 가격 계산

```text
다음 가격 = 이전 가격 × exp(이번 로그수익률)
이번 로그수익률 = 종목별 민감도 × 시장 요인
                + 분야 요인 + 뉴스 영향 + 유저 순매수 영향 + 개별 작은 충격
```

단순 수익률을 더한다는 초기 설명을 양수 가격을 유지하는 로그수익률 모델로 구현했습니다.
각 요인의 수치는 **게임 초기 설정값이며 실제 시장에서 추정한 값이 아닙니다.**
가격은 내부에서 소수점으로 누적해 작은 움직임을 잃지 않고 화면에서 원 단위로 표시합니다.

| 요소 | 초기 구현 |
|---|---|
| 전체 시장 | 직전 요인의 15% + 표준편차 0.022%의 정규 충격. 전체 종목이 공유 |
| 분야 | 직전 요인의 20% + 표준편차 0.027%의 정규 충격. 분야 내부 공유 |
| 동아리별 민감도 | 시장 영향 배율 0.8~1.2. 변동성 특성의 초기 차이 |
| 개별 변동 | 표준편차 0.032%의 정규 충격 × 종목 변동성 배율 |
| 뉴스 | 특정 종목/분야에 유한한 로그수익률 예산을 적용 |
| 거래 | `0.002 × tanh(유저 순매수 주식 수 / 1000)` |

이전 요인은 짧게만 이어받아 긴 확정 추세를 만들지 않습니다. 시장 움직임이 크면
공통 충격 폭을 최대 2.5배로 늘립니다. 종목에 뉴스·체결 압력이 발생하면 개별 변동성은
최대 3배까지 커지고, 새 압력이 없으면 초과 변동성의 10%씩 매 틱 감소합니다.
가격 수준을 최초 가격으로 무조건 되돌리는 규칙은 없습니다.

극단적인 충격에 대한 게임 안정 장치로 한 틱 로그수익률을 `±log(1.01)`로 제한하고
최저 가격을 1원으로 둡니다. 이는 실제 시장 일일 가격 제한폭을 구현한 것이 아닙니다.
상한을 넘은 영향은 이월하지 않고 소진합니다. 동아리별 가격 합계나 시장 총액은
고정하지 않아 한 종목 상승 때문에 무관한 종목이 강제로 하락하지 않습니다.

### 뉴스 영향과 향후 발행 기능

뉴스마다 고유 ID, 종목/분야 대상, 방향을 포함한 영향 크기, 반영 시각을 저장합니다.
영향은 -15%~+15% 범위에서 입력하되 이 수익률 자체가 보장되는 것은 아닙니다.

- 이벤트 예산은 `log(1 + impact)`입니다.
- 다음 30초 틱에서 예산의 60%를 반영합니다.
- 남은 40%는 이후 119틱에 감소하는 가중치로 나눠 반영합니다.
- 총 120틱(약 1시간) 후 영향은 완전히 끝납니다. 종료 시 가격을 원래대로 돌리지 않습니다.
- 다른 뉴스·매도 압력·시장 요인으로 호재 중에도 하락할 수 있습니다.
- 틱 제한에 걸리면 뉴스 영향 일부가 소진되어 입력한 크기보다 작게 반영될 수 있습니다.
- 동일 ID의 재전송은 무시하고, 동일 ID로 대상·영향을 바꾸면 오류를 냅니다.

향후 뉴스 화면에서는 발표 즉시 정보를 보여주고 다음 서버 틱에 반영합니다.
뉴스는 다음 서버 틱부터 가격에 반영됩니다. 체결 시점에 서버의 최신 가격을 다시 확인합니다.

기존의 **1시간마다 무료 분야별 호재·악재 뉴스 제공** 방향을 유지합니다.
관리자가 직접 작성·발행하는 기능은 구현했습니다. 뉴스 콘텐츠 자동 생성/매시간 자동 발행은 후속 작업입니다.

### 모의 체결과 거래 영향

한 틱 동안 서버를 상대방으로 **체결된 유저 매수 수량 - 체결된 유저 매도 수량**을
사용합니다. 전체 거래 양쪽의 매수·매도를 합치지 않습니다. 주문 제출·취소는 제외합니다.

초기 유동성 기준은 모든 종목 1,000주/틱이며 향후 종목별 거래 규모로 조정할 수 있습니다.
순매수 영향은 포화 함수로 제한해 소수 유저의 대량 거래가 가격을 무한히 올리지 않게 합니다.
거래량 필드는 유저 체결의 매수·매도 수량 절댓값 합입니다.

주문은 시장가 방식으로 서버가 상대방이 되어 즉시 체결합니다. 매수가는 기준가의 100.25%,
매도가는 99.75%를 원 단위로 반올림해 계산합니다. 확인창의 금액은 예상값이며 주문을
확인하는 순간 서버의 최신 시장가로 체결합니다. 1회 주문은 1~1,000주이며 잔고와 보유 수량을
서버에서 검사합니다. 동일 주문 ID 재전송은 기존 체결을 반환합니다. 현금·보유 수량·원가·
체결 기록·다음 틱 가격 영향은 같은 PostgreSQL 트랜잭션에 기록합니다. 보유 자산은 현재
매도가를 기준으로 평가합니다. 수수료와 지정가는 아직 없습니다.
주문 화면에서 종목·수량·예상 시장가·예상 금액을 확인한 후에만 주문이 전송되며, 체결 결과는
화면 알림과 프로필의 최근 거래 내역에 표시됩니다. 응답을 받지 못한 주문의 재요청은
같은 주문 번호로 결과를 확인해 중복 체결을 방지합니다.

### 시간·차트·동시성

- 가격 틱: 30초. 초기 버전은 24시간 운영하며 실제 거래소 휴장일/장 시간은 적용하지 않습니다.
- 차트: 5분 단위 OHLCV의 종가를 선으로 표시. 진행 중인 5분 구간도 포함합니다. 가격 눈금,
  시간, 시작가 기준선, 현재 지점과 면적 음영을 함께 표시하며 보유 종목에는 최근 30분 차트를 제공합니다.
- API: 로그인 세션이 필요한 `GET /api/market`. 최근 최대 60개 5분봉(약 5시간)을 반환합니다.
- 오늘 등락률·최고가·최저가: 한국시간 00:00 이후 첫 기록 기준. 자정에 기준을 재설정합니다.
- 카드와 상세는 같은 응답의 같은 이력을 사용합니다. 브라우저에서 난수·가짜 과거를 만들지 않습니다.
- 화면은 10초마다 조회하고 실제 가격은 30초 경계에서 바뀝니다. 최초에는 한 점부터 시작합니다.
- 통신 실패 시 마지막 데이터와 오류 상태를 표시하고 재시도합니다. 로그인 만료 시 로그인 화면으로 이동합니다.
- SQLite 쓰기 트랜잭션 / PostgreSQL 트랜잭션 advisory lock과 `(틱 시각, 종목)` 고유 키로 동일 틱 중복 저장을 방지합니다.
- 서버에만 있는 영속 난수 seed와 틱 시각으로 계산해 요청 횟수·재시작에 따라 경로가 달라지지 않습니다.
- seed·향후 가격·내부 요인별 기여도는 공개 API에 노출하지 않습니다.
- 서버 중단 후 틱을 순서대로 복구합니다. 한 번에 최대 240틱(2시간)을 처리하고
  `catchingUp=true`를 반환합니다. 화면/CLI가 반복 호출해 나머지를 복구합니다.

### 저장 및 운영

현재 회원 정보는 기존 Supabase를 사용합니다. `DATABASE_URL`을 설정하면 시장·관리자·인증 데이터는
PostgreSQL의 `stockolon_private` 스키마에 저장합니다. 주소를 설정하지 않은 로컬 개발 환경은
`instance/market.sqlite3`에 저장합니다. 환경 변수 `MARKET_DATABASE`로 경로를 바꿀 수 있습니다.
DB는 최초 실행 시 생성되며 모든 종목은 공정하게 10,000원에서 시작합니다.

SQLite는 별도 접속 설정 없이 검증할 수 있는 **단일 서버 초기 구현**입니다.
같은 서버의 여러 Flask/Gunicorn 워커 및 시장 CLI는 반드시 동일 파일을 공유해야 합니다.
컨테이너 재시작 시에도 유지되는 로컬 영속 볼륨을 사용하고 파일을 백업합니다.
무료 Render와 여러 호스트 환경에서는 추가된 PostgreSQL 저장소를 사용합니다.
자세한 구성은 [무료 Render 안내](docs/render-free.md)를 참고하세요.

테이블: `market_state`, `market_stocks`, `market_ticks`, `market_candles`,
`market_news`, `market_flows`. 원시 틱에는 요인별 기여도를 저장해 원인을 분석할 수 있습니다.
33종목 기준 하루 약 95,040개 원시 틱이 생성되므로 원시 틱은 6시간, 5분봉은 7일로
보관 기간을 제한합니다. 현재가·뉴스 이벤트·관리자 계정은 이 정리에서 삭제하지 않습니다.

## 관리자 계정과 운영 화면 (2026-10-29)

관리자 로그인: `/admin/login` · 관리창: `/admin/`.
일반 로그인 화면 `/auth/login`에서도 학번 대신 관리자 아이디를 입력해 로그인할 수 있습니다.
관리자 아이디가 학번과 같다면 관리자 계정이 우선합니다. 관리자 로그인 시도 제한과
최초 로그인 시 비밀번호 변경 절차는 두 로그인 화면에 동일하게 적용됩니다.

일반 회원은 로그인 화면의 비밀번호 찾기에서 가입한 학번과 학교 이메일을 입력하고,
메일 인증번호로 새 비밀번호를 설정할 수 있습니다. 인증번호는 10분간 유효하고 한 번만
사용할 수 있습니다. 관리자 계정은 이 기능을 사용하지 않습니다.
회원가입과 비밀번호 찾기의 이메일 인증은 같은 이메일 주소당 한국 시간 하루 최대 5회이며,
발송에 실패한 요청은 일일 한도에서 제외됩니다. 기존 재발송 대기 및 단기 요청 제한도 적용됩니다.
가입할 때 선택한 동아리의 로고가 메인 화면과 각 페이지의 프로필에 표시됩니다.
소속이 없거나 프로젝트에 로고 파일이 없는 경우 기본 이미지가 표시됩니다.
일반 Supabase 회원과 **별도의 관리자 계정**을 사용합니다. 회원가입 양식의 값이나
쿠키의 `role`/`is_admin` 값으로 관리자 권한을 얻을 수 없습니다.

| 권한 | 시장 현황 | 뉴스 발행·작업 기록 | 관리자 생성·비활성화 |
|---|---|---|---|
| 최고관리자 `owner` | 가능 | 가능 | 가능 |
| 운영관리자 `editor` | 가능 | 가능 | 불가 |
| 일반 회원/비로그인 | 관리자 화면 접근 불가 | 불가 | 불가 |

### 최초 계정 만들기와 복구

```bash
# 해당 서버의 같은 MARKET_DATABASE와 SECRET_KEY를 사용한 터미널에서 실행
flask --app run admin create --username admin --role owner
# 비밀번호는 화면에 표시하지 않고 두 번 입력합니다 (12~128자).
# 자동 임시 비밀번호를 터미널에 한 번 표시하려면 --generate 사용.
flask --app run admin create --username operator --role editor --generate
# 분실 시 서버 소유자가 복구. 기존 세션은 모두 무효화합니다.
flask --app run admin reset-password --username admin
```

기본 비밀번호나 공개 관리자 가입 URL은 없습니다. 최초 발급/복구 비밀번호는 로그인 후
반드시 변경해야 시장 조회·뉴스 발행·계정 관리를 사용할 수 있습니다.
최고관리자는 관리창에서 추가 관리자를 만들 수 있습니다. 마지막 활성 최고관리자와
현재 로그인한 본인은 비활성화할 수 없습니다. 다른 관리자를 비활성화하면 기존 세션도 종료합니다.

이 컴퓨터에 생성한 계정은 **로컬 시장 DB**에 있습니다. 계정·비밀번호·세션은 Git에
포함되지 않으므로 배포 서버에서도 위 CLI로 별도 생성해야 합니다. 배포 시 같은 영속 DB를
웹 서버와 CLI가 공유해야 합니다. HTTPS 환경에서 `SESSION_COOKIE_SECURE=1`을 설정하고,
길고 임의적인 `SECRET_KEY`를 모든 워커에서 동일하게 유지합니다.

### 운영 기능

- 33개 종목의 현재가·오늘 등락·고가·저가를 10초마다 조회합니다.
- 제목·본문·영향 분야/동아리·영향 크기를 지정해 뉴스를 발행합니다.
- 기사는 발행 즉시 일반 `/news`에 표시되고 다음 30초 주가 틱부터 반영됩니다.
- 기사·가격 이벤트·감사 기록은 **한 DB 트랜잭션**으로 저장합니다.
- 같은 발행 요청을 재전송해도 기사와 가격 영향은 중복 적용하지 않습니다.
- 공개된 뉴스는 가격 영향을 이미 줄 수 있어 편집·삭제·가격 초기화 버튼을 제공하지 않습니다.
- 최근 50개 발행 기사와 최근 50개 로그인·발행·계정 작업 기록을 볼 수 있습니다.

### 인증과 저장

인증 메일은 HTTPS API를 지원하며 코드는 DB에 HMAC으로 저장합니다. 브라우저 쿠키에는 요청 ID만 보관합니다.
비밀번호는 Werkzeug 해시로 저장합니다. 관리자 세션은 DB에 토큰의 해시만 저장하고
최대 8시간 후 만료합니다. 모든 요청에서 계정 활성 상태와 현재 권한을 다시 검사합니다.
비밀번호 변경·복구·로그아웃·계정 비활성화는 관련 서버 세션을 무효화합니다.
로그인 및 모든 관리자 POST 양식에 CSRF 토큰을 검사합니다.
계정별 15분 동안 5회, IP별 20회의 실패 제한을 DB에 저장합니다.
페이지/응답은 캐시하지 않고 프레임 삽입을 차단합니다. 기사 본문은 HTML로 실행하지 않습니다.
비밀번호·해시·세션 토큰은 작업 기록에 남기지 않습니다.

관리자 테이블: `admin_accounts`, `admin_sessions`, `admin_login_limits`, `admin_audit`.
기사 테이블: `news_articles` (기존 `market_news`의 가격 이벤트와 연결).

검증: 관리자 권한 위조 차단, 최초 비밀번호 변경, CSRF, 계정별 권한 차이,
비활성화/로그아웃/비밀번호 변경 후 세션 재사용 차단, 만료·실패 제한,
발행 중복 방지·트랜잭션 롤백·HTML 이스케이프·CLI 복구를 자동 테스트합니다.

## 로그인·회원가입 화면 정리 (2026-10-29)

기존 색상(배경 `#111111`, 입력창 `#2f2f32`, 주요 버튼 `#00d96f`,
이메일 버튼 `#00ff99`, 기존 텍스트·테두리 색상)을 유지하고 배치와 동작을 정리했습니다.

- 로고와 입력창·버튼 크기를 줄이고, 중앙 정렬·일정한 간격을 적용했습니다.
- 입력 필드에 고정 라벨과 자동 완성 정보를 추가했습니다.
- 회원가입을 기본 정보·이메일 인증·비밀번호 영역으로 나눴습니다.
- 데스크톱의 이름/학번·비밀번호/확인은 두 열, 모바일에서는 한 열로 배치합니다.
- 이메일 주소·도메인·인증 버튼의 높이를 맞추고 좁은 화면에서도 넘치지 않게 했습니다.
- 잘못된 입력을 편집/제출한 뒤 해당 필드 아래에만 오류를 표시합니다.
- 이메일 발송 중·성공·실패·60초 재발송 대기를 알림창 대신 화면 안에서 안내합니다.
- 로그인 서버의 오류 메시지를 화면에 표시하고 로그인/회원가입 이동 링크를 정리했습니다.
- 로그인 화면에 별도의 관리자 로그인 링크를 추가했습니다.

브라우저 검증: 320/390/768/1440px 레이아웃, 기존 색상 값, 오류 표시,
로그인 제출, 회원가입 이동, 이메일 발송 성공/실패(테스트 응답 사용),
재발송 상태와 비밀번호 일치 검사를 확인했습니다. 실제 이메일을 발송하거나
Supabase에 테스트 회원을 생성하지 않았습니다.
